# Next + Convex + Vercel scaffold

Starter for a full-stack app.
Bun workspaces monorepo, Next.js (App Router) + Tailwind v4 + shadcn, Convex backend with Google sign-in via Convex Auth.

## Layout

- `convex/` — Convex schema, functions and auth (shared backend, lives at the repo root; `apps/web/convex.json` points here)
- `packages/core/` — `@scaffold/core`: Convex API re-exports, zod schema helpers and other React-free shared code; React hooks under `@scaffold/core/hooks`. Pure helpers used by Convex functions live here too, since every file under `convex/` is pushed as a module.
  - `src/dates.ts` — calendar dates as ISO `YYYY-MM-DD` strings (`IsoDateSchema`, `parseIsoDate`, `todayIso`, `addDays`, `daysOf`, …), with the arithmetic on `@internationalized/date`'s `CalendarDate` so no DST shift can move a day; `src/format.ts` formats amounts, quantities and dates per locale for output made outside React (`formatMoney`, `formatLongDate` and friends).
  - `src/zod-field-errors.ts` — `zodFieldErrors(schema, error)` maps a Convex mutation's args rejection onto the form's fields, `fieldValidationError(field, message)` throws the same shape from a server-side check.
  - `src/secret-box.ts` — `sealSecret` / `openSecret` seal third-party credentials as compact JWEs (jose, `dir` + `A256GCM`) with a 32-byte key that `decodeSecretBoxKey` reads from a deployment variable of the app's choosing; nothing uses it yet, so wire one up (a `@scaffold/core/server` helper naming the variable, a line in `scripts/generate-env.ts`, `bunx convex env set` on every deployment) with the first credential the app stores.
  - `src/jwt.ts` — `jwtExpiresAt`, the unverified `exp` of a token, for the proxy.
- `packages/i18n/` — `@scaffold/i18n`: every user-facing string, as next-intl messages under `src/translations/<locale>/<namespace>.json` (`global`, `nav`, `auth`, then one per page or feature: `home`), typed through `global.d.ts`; a new namespace is registered in every locale's `index.ts`. Components that render synchronously (client or server: `Button`, `LoadingOverlay`, …) call `useTranslations` from `@scaffold/i18n`; async server components (`'use cache'` content, layouts, `generateMetadata`) await `getTranslations` from `@scaffold/i18n/server`; `t.rich` gets `<b>`, `<small>` and `<code>` by default. Locales are listed in `src/locales.ts` (`LOCALES`, `parseLocale`, the `NEXT_LOCALE` cookie name), also exported next-intl-free as `@scaffold/i18n/locales` for `packages/core` and `convex/`; every locale directory must mirror `en` key for key, which `translations.test.ts` enforces. The app registers the messages in `apps/web/src/i18n/request.ts` (through `createNextIntlPlugin` in `next.config.ts`), reads the language from the cookie the header's `LocaleToggle` sets via the `setLocale` server action, and mounts `NextIntlClientProvider` in the root layout. `'use cache'` content components cannot read that cookie: the page reads `getLocale()` once and passes `locale` down, and the content calls `getTranslations({ locale, namespace })`; sync components rendered inside cached content (`Button`) are `'use client'` for the same reason. Timestamps are shown in the browser's time zone, which `TimeZoneCookie` reports to the server (`src/time-zone.ts`; UTC until then); render them with `DateTime` (`apps/web/src/components/date-time`). Code that runs outside React and outside a request (a Convex action) gets a translator from `getStaticTranslator(locale, namespace)` in `@scaffold/i18n/translator`.
- `packages/ui/` — `@scaffold/ui`: shadcn components (`@scaffold/ui/components/*`), reusable composites built from them under `src/layouts/<name>/` (`@scaffold/ui/layouts/<name>`: `data-table`, `empty-state`, `page-container`, `page-header`, `sidebar-layout`, `confirm-dialog`, `row-actions-menu`, `loading-overlay`), UI hooks under `@scaffold/ui/hooks` (`useDrawer` for dialog/sheet open state + payload, `useIsOpen` for open state alone), `cn`, the Tailwind theme (`src/styles/globals.css`)
- `packages/forms/` — `@scaffold/forms`: react-hook-form field components (InputField, SelectField, DateField, …) built on `@scaffold/ui`
- `apps/web/` — the Next.js app; Convex CLI commands run from here

## File layout rules

- File names are kebab-case (`number-field.tsx`, `dev-sign-in.ts`); exported symbols stay PascalCase/camelCase. Exception: Convex rejects hyphens in module paths, so files directly under `convex/` are single words (`users.ts`) and helpers shared by Convex functions live in `@scaffold/core/server` (`packages/core/src/server/`: `requireUserId`), which may import `@convex-dev/auth/server` and is never imported by browser code.
- Component props are never typed inline: declare a `<Component>Props` interface (or type) directly below the component, after its body (`function UserMenu({ preloadedViewer }: UserMenuProps) { … }` then `interface UserMenuProps { … }`). Next.js `layout.tsx` / `page.tsx` default exports keep the framework's `{ children }` signature.
- A component lives in its own directory with everything that belongs only to it: `number-field/number-field.tsx`, `number-field/number-input.ts`, `number-field/number-input.test.ts`.
- Tests are colocated next to what they test (`*.test.ts`, run by `bun test` from the root). Compile-time fixtures use `*.typecheck.tsx` and are only picked up by `tsc`.
- Package-private helpers go in that package's `src/utils/<name>.ts`; helpers shared by several packages go to `packages/utils` (create it when first needed).
- Pages stream: `page.tsx` renders `<Suspense fallback={<XPageContent data={null} />}><SuspendedXPage /></Suspense>`, where `SuspendedXPage` is the async server component that awaits the auth token and `preloadQuery`s, and `content.tsx` (`'use cache'`) renders the page for the data or its skeleton state for `null` (see `app/(app)/page.tsx`). Client components take `Preloaded<…> | null` and read it with `useOptionalPreloadedQuery` from `@scaffold/core/hooks`, rendering their own skeleton state for `null`, so the fallback is the same component tree with `null` data (no skeleton twins, no ternaries). Never `await` Convex in a layout or page body outside such a boundary.
- Pages wrap their content in `PageContainer` (`@scaffold/ui/layouts/page-container`); the app's `<main>` is edge to edge so that a section layout (`SidebarLayout`) can own the full width.
- The proxy decides the login redirect from the JWT `exp` alone (`jwtExpiresAt`); it never calls Convex, since that would sit in front of every page's first byte.
- In `apps/web`, `src/components/` is only for components reused across routes. One-off UI is inlined into the page or, when large, colocated in the route directory (`app/login/content.tsx`). Client components are split into their own `'use client'` files under a `partials/` directory next to the server file that renders them (`app/login/partials/sign-in-buttons.tsx`, `app/(app)/partials/user-menu.tsx`); keep pages and layouts server components.

## Conventions

- Bun everywhere: `bun install`, `bun run <script>`, `bunx <pkg>`, `bun test`. Third-party packages used across the workspace (`lodash`, `type-fest`, `convex`, `zod`, …) are declared once in the root `package.json`; type-only packages (`type-fest`, `@types/*`) go under devDependencies. Package-specific deps stay in that package.
- Biome formats and lints (4 spaces, single quotes, no semicolons, 120 cols). Run `bun run lint` before finishing; `bun run lint:fix` auto-formats.
- Avoid type predicates (`x is Y`) and casts; they hide type errors. Model unions so TypeScript narrows on its own, e.g. a discriminant like `id: string` vs `id?: never` checked with `column.id !== undefined`.
- Forms: zod schema in `packages/core`, `useForm<z.input<typeof S>>({ resolver: useZodResolver(S), mode: 'onTouched', defaultValues })` with `useZodResolver` from `@scaffold/forms` (never `zodResolver` directly), fields from `@scaffold/forms` bound with `control`. The resolver reports field errors but `handleSubmit` receives the raw form state, which goes straight to a Convex mutation taking the same schema (see below); the server does the parsing. Forms saving through a mutation use `useSaveForm` + `SaveForm` (`apps/web/src/components/save-form`), which owns the lifecycle and maps the server's field errors from the schema itself; elsewhere map server rejections back onto fields with `zodFieldErrors(S, error)` from `@scaffold/core`; a server-side check that belongs on one field (a name already taken) throws `fieldValidationError(field, message)` so it lands the same way. Field `name`s are constrained to paths of the matching value type: `InputField`/`TextareaField`/`SelectField`/`DateField`/`TimeField` → `string`, `NumberField` → `number | null`, `CheckboxField` → `boolean`.
- Form state never holds `undefined` (react-hook-form resets such a field to its default value). Empty text is `''`, empty number is `null`; schemas use `optionalString` / `optionalNumber` / `requiredNumber` from `@scaffold/core` so the parsed output has clean `undefined`s. Always give every field a default value.
- Add shadcn components from `apps/web` with `bunx shadcn add <name>`; they land in `packages/ui/src/components`. Anything reusable that composes several of them (tables, empty states, page shells, …) is a layout in `packages/ui/src/layouts/<name>/` with an `index.ts`; app code imports it from `@scaffold/ui/layouts/<name>`.
- Lists render through `DataTable` from `@scaffold/ui/layouts/data-table`: typed `TableColumn<Row>[]` definitions (`key` is a dotted row path like `'contact.email'` via type-fest `Paths`, no array indices, read with lodash `get`; `format`/`render` get the value at that path; `id` for custom columns), `getRowKey`, optional `search` over `searchable` columns. Columns use the browser's auto layout by default; `width: 'content'` shrinks a column to its content (numbers, dates, actions), `width: 'fill'` hands one the remaining space; `ellipsis` truncates long text without affecting the column's share of the width. A column with `id: 'actions'` and no `header` gets a visually hidden "Actions" heading by default.
- A create-only flow is a self-contained `<New|Create>XDialog` partial next to the page that uses it: trigger button + dialog + form (`projects/partials/new-project-dialog.tsx`). Only when a page also edits from several places does a `<X>DialogProvider` own `useDrawer<Doc>()` state and expose `use<X>Dialog()` (`open()` creates, `open(doc)` edits, the form takes `initialValues`).
- Destructive actions (disconnect, delete) sit behind `ConfirmDialog` from `@scaffold/ui/layouts/confirm-dialog`: the trigger button, a title naming the action, one line on what is lost, and the action itself as `onConfirm`, which reports its outcome with a toast. A table row's actions go in a `RowActionsMenu` (`@scaffold/ui/layouts/row-actions-menu`, the "…" button with `DropdownMenuItem`s); a destructive item opens a controlled `ConfirmDialog` (`open` / `onOpenChange` from `useIsOpen`, no `trigger`, the menu's `ref` as `returnFocusTo`) rendered next to the menu.
- User feedback for finished actions (saved, created, failed request) is a toast: `toast.success/error/warning/info` from `sonner`; the single `Toaster` (`@scaffold/ui/components/sonner`, wrapped by `app/partials/app-toaster.tsx` for the theme) is mounted in the root layout. Inline copy is only for field-level validation errors.
- Copy lives in `@scaffold/i18n`, never inline: labels, placeholders, toasts, aria labels, empty states, metadata titles (`pageTitle(t('metadataTitle'))`). Enum-like labels are keyed by the value (`global.theme.<theme>`, `global.language.<locale>`), so `packages/core` keeps ids only. Words shared across pages (Name, Email, Total, Cancel, Save changes, …) live in `global` and are passed by key without a second translator in the parent: `labelKey` on every form field and on `Button`, `headerKey` on table columns; anywhere else a component declares a second translator (`const tg = useTranslations('global')`) rather than mixing in `<Translate>`. `<Translate namespace value />` is only for places where hooks cannot run, i.e. module-level constants (table columns, nav items), which hold keys (`as const satisfies …[]`) or `<Translate>` elements, never strings. Still in English in code, by design: zod validation messages and `ConvexError` messages, since `packages/core` and `convex/` are shared with the server and cannot depend on next-intl.
- Icons: always import the `Icon`-suffixed lucide names (`PlusIcon`, `UsersIcon`, `type LucideIcon`), never the bare ones, so icon names never clash with our own components.
- Convex functions with arguments use the zod plugin (`convex-helpers/server/zod4`): `const zMutation = zCustomMutation(mutation, NoOp)`, then `zMutation({ args: SomeSchema.shape, handler })`. Args on the wire are the schema *input*, the handler receives the parsed *output*, so browser and server share one schema and nothing is validated twice by hand. `zid('table')` for ids. Functions that must not run anonymously start with `requireUserId(ctx)` from `@scaffold/core/server`.
- Third-party API calls run server-side only (Convex actions). A credential is handled by the browser only transiently, in the form that submits it: it is persisted only sealed (`sealSecret` / `openSecret` from `@scaffold/core`), is never logged, and is stripped from every query result.
- Never set `DEV_SIGN_IN_AS` on the production deployment.
